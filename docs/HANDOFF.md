## 当前产品与运行边界

本轮 1.6.3 延续“收藏与订阅”，增加“探索 → 社区交流”：技术问答、经验与建议、项目动态、问题反馈组成项目交流信息流。用户可搜索、按收藏项目筛选、打开来源项目或讨论，选择已审核项目并用 Markdown 发帖。项目审核范围保持，讨论和回复直接参与。

1.6.2 已上线个人分类、标签备注、批量整理、GitHub Release 消息和已读管理、个人 GitHub Stars 分页及逐项私有导入、项目 AI 分析。Key 填写、三种模型服务及升级顺序见[集成指南](FORGE_INTEGRATIONS.md)。当前代码、远程部署与设备证据分别查验收记录。

主导航沿用 1.6.0 的“探索 / 我的仓库 / 校园 / 我的”，默认展示已审核项目。探索负责公开发现；我的仓库管理本人全部项目、GitHub 绑定和逐项目审核状态。项目详情承接 README、源码链接、Star 和 Issue 式讨论回复，沿用华师大归属核验与公开范围规则。

1.6.1 已实现：探索加入全部项目/我的 Star 与更新、创建、名称排序；项目正文、讨论及回复使用 Markdown，提供编辑预览、链接打开与代码复制；Issue 增加关键词、类型、状态组合查询及日期显示。话题点击沿用关键词搜索。Star 用于收藏归集，讨论订阅、站内消息、角色、指派、里程碑和 Git 托管/运行器属于后续。设计依据与范围见[设计对标](DESIGN.md#功能对标与本轮落点)，实际验证和发布阶段查验收记录。

校园分为“课程与课表 / 快速访问 / 校园广场”。保留课程列表、课表 CSV 导入、基本课程详情和真实通知；公共官方服务与个人收藏分别管理。约球、竞赛组队、学习搭子和扩列保留在校园广场。个人页集中账号、项目、收藏、通知、设置与关于。

笔记、PDF、AI 学习、复习卡片从客户端主流程撤下。旧源码、集合和网关作为存量实现保留，本轮聚焦入口和产品范围调整。1.6.0 的源码改动、发布结果和操作验收分别登记；下面的学习功能记录属于此前版本。

主要产品链路为 Flutter → PocketBase，支持 Web、Android、Windows。官网与运营台连接同一服务；Node.js 网关处理 GitHub 集成和项目分析，旧 EduWork 学习模块与 NestJS/PostgreSQL 实现按存量参考管理。

当前公开配置仍指向 campus.allezafrique.cn；正式目标 campus.scsldr.cn 的备案、TLS 和设备恢复按[域名流程](DOMAIN_FILING.md)推进。最近有证据的部署版本、备份和测试数量统一见[验收记录](ACCEPTANCE.md)。

当前 Web 为 1.6.3，来源 `e266b18`，Android 与 Windows 云包均为同一提交。收藏库迁移已执行，项目分析模块为 `e200256`。普通账号公网调用、浏览器重载和管理员独立读回证据见验收记录；原生设备继续按下一节验收。官网六页沿用项目社区定位。

### 试用时最少填写与检查

1. 打开 Web 或安装来源为 `e266b18` 的 1.6.3 云包，用已验证普通账号登录。先在“探索 → 社区交流”查帖子、选择项目发帖并回复，再检查重启读回。
2. Star、分类、备注和版本订阅直接使用 Campulse 账号。需要读取个人 GitHub Stars 时，在“我的 → 设置 → GitHub 与 AI 设置”填个人 Token；fine-grained Token 的 Account permissions → Starring 设为 Read-only，然后点“检查 GitHub”和保存。
3. 当前站点可直接选 ChatECNU 使用已配置服务；切换 DeepSeek 时填写自己的 API Key，模型留空采用服务端默认值，先测试模型再保存。自部署 EduChat 先由管理员配置服务地址与模型。
4. 使用真实校园项目完善介绍、README、源码链接和学校归属材料，逐项提交审核。管理员核验并批准后，用第二账号检查探索、社区交流、Star 与回复。
5. 原生设备、邮件收件、正式域名与微信资质分别完成专项验收。2026-10-22 已将 MuMu 中的 Campulse 从 1.2.0 保留数据升级至 1.6.3、构建号 1049，云包来源、SHA256、签名及设备版本均已核对。两个 ADB 连接指向同一设备，当前为 MAA 连接的《明日方舟》实例；安装前后游戏保持前台。设备空闲后打开 Campulse，继续登录保持、点击和重启读回；浏览器/API 证据与设备结果分开登记。

## 工作约定

- 分支使用 main，按范围明确暂存，推送与服务器部署分开记录。
- 产品版本固定 `1.6`，每轮只将第三段加一，本轮为 `1.6.3`；CI 构建号独立递增，发布时同时核对产品版本、来源提交与构建记录。
- APK、校验与来源元数据发布到 GitHub Releases，main 保留源码和下载说明，云任务完成后直接结束。
- 修改前检查工作区，保留无关用户修改。凭据、SSH 私钥、.env 与测试原始日志留在 Git 忽略位置。
- 按改动范围部署客户端与页面；涉及服务或数据库时再更新对应部件，共享服务器的其他网站保留。
- 结论标明代码实现、部署、API、设备四层证据。历史通过引用日期，外部审批进度按控制台当前结果确认。
- 文档使用固定入口，避免再为每轮生成同主题日期文件。历史详细差异使用 Git 追溯。
