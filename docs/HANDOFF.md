## 当前产品与运行边界

2026-10-16 前端对标改造：任务时间分组、资料库分类搜索、到期复习入口、仓库话题和源码跳转已进入客户端；主题、面板、焦点与卡片层级统一。各功能参考与实际落点见[设计对标表](DESIGN.md#功能对标与本轮落点)。本轮沿用现有后端与迁移，发布包目标 1.3.0；构建和设备证据见验收记录。

2026-10-16 整体界面改造与校园广场：首页工作台、课程搜索/置顶、服务收藏视图和个人工作区已进入客户端；Windows 工程及独立云构建新增，详见[桌面与同步](DESKTOP.md)。校园广场新增 `1790210013_campus_square.js`，包含召集、报名、活动讨论和兴趣名片；服务端迁移先于新客户端验收。部署结果和运行版本统一查验收记录。

客户端信息架构为首页、课程、应用、我的。课程按列表/课表组织，智能体属于课程内部能力。应用分公共快速访问、校园作品和校园广场；项目逐项提交华师大归属审核，项目讨论继承项目权限。广场面向已验证邮箱的用户，活动与兴趣名片按各自归属和可见性管理；邮箱验证与学校归属审核分开。

主要运行链路为 Flutter → PocketBase，AI 请求经 Node 网关调用 ChatECNU。网关复用固定来源的 EduWork 核心模块。旧 NestJS/PostgreSQL 实现保留，现网业务使用 PocketBase。

当前公开配置仍指向 campus.allezafrique.cn；正式目标 campus.scsldr.cn 的备案、TLS 和设备恢复按[域名流程](DOMAIN_FILING.md)推进。最近有证据的部署版本、备份和测试数量统一见[验收记录](ACCEPTANCE.md)。

## 下一步执行顺序

1. 读 Release 元数据、生产迁移列表与网关来源，确认源码/安装包/生产差异。
2. Android 与 Windows 安装同一来源提交的云构建包，先由本人登录普通已验证账号，再按[双端八步验收](DESKTOP.md#双端操作验收)操作。设备认证输入交给用户，其他导航、保存、刷新与记录核对由开发者继续。
3. 邮箱验证与密码重置完成实际收件链路。
4. 微信账号满足客服明确的跳转范围条件后做真实手机验收。
5. 正式域名四项网络检查与手机同步通过后统一配置，再云构建。
6. 本轮 open-code-review 已覆盖 33 个变更文件与 12 个跟进文件，修复及误报核实见[验收记录](ACCEPTANCE.md)。后续对新增变更做定向复核，历史超时轮次与完整仓库审查单独登记。

扩展需求集中到[路线图](ROADMAP.md)。OCR、语义检索、长对话分段、社区通知与贡献流程在现有主链路稳定后推进。

## 工作约定

- 分支使用 main，按范围明确暂存，推送与服务器部署分开记录。
- 修改前检查工作区，保留无关用户修改。凭据、SSH 私钥、.env 与测试原始日志留在 Git 忽略位置。
- 生产升级先备份，应用增量迁移后更新网关/页面，再验收 APK；共享服务器的其他网站保留。
- 结论标明代码实现、部署、API、设备四层证据。历史通过引用日期，外部审批进度按控制台当前结果确认。
- 文档使用固定入口，避免再为每轮生成同主题日期文件。历史详细差异使用 Git 追溯。

本轮整理前的完整文档含用户未提交内容，已备份至本机 .tools/docs-before-cleanup-*；过期文档从当前目录清理，第三方许可与来源文件保留。业务代码、数据库和远程配置沿用整理前状态。
