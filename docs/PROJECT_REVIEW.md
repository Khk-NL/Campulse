# 校园项目审核

更新：2026-10-21。“我的仓库”显示本人全部项目，支持绑定 GitHub。每个项目由作者独立提交审核，并显示状态与处理意见。

## 公开边界

管理员核验华东师范大学归属、用途与内容，批准后项目进入校园作品、搜索和探索。公开/私有可见性与审核状态共同决定访问范围。

- 探索与社区交流：公开、审核通过、华师大归属已核验的校园相关项目。搜索、Star 筛选和讨论信息流沿用该范围。
- 我的仓库：按当前作者展示全部项目，包括个人练习、外部 GitHub 导入、私有、草稿、待审、退回和已上架项目。这里的全部展示指本人工作区内的展示。
- 校园相关性：管理员结合项目用途、README 和归属材料判断，例如面向校园的工具、课程实践及师生协作项目；审批时一并确认。作者具有华师大身份与项目适合校园公开分发分别核实。

讨论和回复按 Issue 模式直接交流，继承所属项目权限。个人课程、笔记、计划与私有项目按账号隔离；Star 表示用户对获准公开项目的关注。

讨论列表按全部、讨论中和已解决筛选，服务端保持项目范围和分页。校内外部社区介绍作为管理员维护的公共资源进入快速访问，与作者提交的社区项目分别存储；引用介绍页与同步原平台内容分别处理。

## 操作顺序

1. 作者创建项目，填写介绍、README、归属材料及可选 GitHub 链接，保存为草稿。
2. 在该项目点击提交审核，进入待审核状态；各项目分别处理。
3. 管理员在审核队列核实学校归属、校园相关性与公开内容，勾选确认后通过上架，或填写意见退回修改。
4. 获准公开后，其他用户可以发现、关注、发起问题与回复。
5. 作者编辑后恢复草稿，重新提交；讨论随项目可见范围变化。

状态在界面中显示为待提交、待审核、已审核或待修改。最终字段与枚举以迁移及 Repository 为准。

## 实现

- forge_repositories 存储项目与审核信息，forge_discussions/replies/stars 存储互动。
- 迁移 1790210010 建立社区集合；1790210011 增加逐项目审核及学校核验约束。
- ForgeRepository 负责本人仓库、公开发现、草稿保存和独立提交。
- 运营台 AdminClient.reviewProject 读取最新记录并处理审核，批准前检查归属材料与学校范围。
- 普通用户只能通过允许的状态提交；核验字段及审核意见由管理员维护。

部署使用固定提交和增量迁移，先备份。实际生产/设备验证见[验收记录](ACCEPTANCE.md)，管理步骤见[运营台](ADMIN_CONSOLE.md)。
